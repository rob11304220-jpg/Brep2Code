# ADR-0062: Deliver Hosted Evidence Through a Five-Family Capability Portfolio

- **Status**: Accepted
- **Date**: 2026-08-11

## Context

The repository has broad, family-scoped offline sequence evidence but only small hosted smokes. Counting cases or terminal hosted passes would not show whether the observation-only Harness handles distinct construction dependencies.

## Decision

Use five bounded mechanism families as the minimum hosted-capability portfolio: prismatic base with parameterized cylindrical cut; dependent face selection; multi-inner-loop pocket; repeated feature pattern; and axisymmetric revolve. Each family first has a mechanism dossier and frozen offline release. Hosted work proceeds one family at a time, from development evidence through independent review to a separately selected held-out campaign.

`fillet`/`chamfer` is a peer CAD mechanism, but a sixth, post-portfolio edge-finishing extension. `shell` or `rib` remains a later complex-topology extension.

## Consequences

- The case portfolio gains a read-only five-family delivery projection; case records, manifests, packs/cards and reports remain authoritative.
- The new route does not promote a case to a runtime card, executable manifest or provider scope.
- A hosted pass is recorded in the hosted registry only after terminal review; all campaigns still need fresh G3 preflight and itemized authorization.
