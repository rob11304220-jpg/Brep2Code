# WP-M20-001: Sequence-Paired Prismatic-Hole Foundation

- Status: done
- Milestone: M20
- Owner: Codex

## Goal

Establish and validate, offline, the smallest sequence-paired benchmark for
recovering an editable prismatic base plus one cylindrical subtractive feature.
The workpack must determine whether the proposed canonical sequence and
three-layer evidence can support later controlled case growth.

## Scope

- Define a versioned, development-only canonical grammar for one planar sketch,
  one base extrusion, and one through/blind/counterbore cylindrical cut.
- Define the paired-case metadata, source-oracle provenance, split/family rules,
  deterministic OCP replay, and auditable geometry/sequence/editability checks.
- Create only a small preregistered seed set with family-isolated development
  and held-out cases; record selection before interpreting outcomes.
- Reuse existing OCP and Harness geometry gates as layer one without modifying
  them.
- Produce an offline review that either recommends a separately governed
  controlled-expansion workpack or records why the pilot must be revised or
  retired.

## Attribution question and sampling intent

Distinguish whether a restricted, declared construction grammar can provide
auditable sequence and editability evidence beyond final-B-Rep similarity.
The seed set must cover through, blind, and counterbore variants while holding
out whole declared families.  Stop after the preregistered seed set: do not
replace failures, widen the grammar, or add cases to improve a result.

## Inputs

- Existing self-authored OCP cases and parameter-family assets, used only when
  their source/oracle status is declared.
- Existing geometry probe and Harness gate implementation.
- The planning decision in ADR-0018 and the sequence-paired route roadmap.

## Code paths

- `case-library/self-authored/` and a new explicitly scoped pilot location if
  required by the approved metadata design.
- `tools/` for deterministic replay and auditing only.
- `tests/` for grammar, split, replay, and editability coverage.

## Trace/schema changes

No `signal_bundle.json`, provider trace, tool trace, corpus report, storage
layout, or CLI JSON change is authorized.  Pilot metadata is development-side
case evidence and is not a Harness runtime schema or a modeling IR.

## Compatibility constraints

- Keep default execution network-free and credential-free.
- Do not modify existing Harness gates, CLI commands, self-authored manifests,
  Fusion parser/replay scope, ABC boundary, hosted policy, runtime resources,
  prompt, SDK, or IR behavior.
- Preserve existing fixture paths and case-library authority under ADR-0014.
- No candidate becomes a default fixture, corpus selection, provider input, or
  training input solely because it is generated by pilot tooling.

## Acceptance

- A developer can read one contract and determine supported operations,
  normalization, oracle provenance, dependencies, and all three pass layers.
- The small seed set is preregistered with family-disjoint development and
  held-out splits before outcome review.
- Every seed case passes deterministic replay and existing geometry gates;
  sequence agreement and preregistered editability checks are independently
  auditable.
- The audit rejects unsupported, ambiguous, hash-mismatched, split-leaking, or
  non-deterministic cases without fallback.
- A completion review explicitly recommends promotion, revision, or retirement;
  it cannot silently promote the pilot to a general case-production process.
- Run focused tests plus:

```powershell
uv run python -m pytest
uv run python -m ruff check .
```

## Evidence reuse / guidance-card disposition

No reusable runtime guidance is assumed.  Completion must record exactly one:
a source-linked experience card, a counterexample, or no reusable evidence.
Any card remains subject to ADR-0016 and does not authorize retrieval.

## Status transition

On completion update `docs/workflow/status.md`, this workpack, the workpack
index, the active handoff, and the completion review.  Create a new ADR and
maintenance-runbook change only if review promotes a lasting governance rule.

## Out of scope

General B-Rep-to-history recovery; operation types beyond the stated family;
Fusion expansion; DeepCAD admission; automatic case admission; hosted/provider
evaluation; training/fine-tuning; runtime IR; project CAD SDK; Harness or gate
changes; and any benchmark-quality claim.

## Repair hypothesis and evaluation boundary

This is an offline development-side evidence foundation, not a generated-script
repair experiment.  It makes no hosted or held-out model-performance claim.

## Notes

The workpack begins with grammar/oracle design and preregistration.  It must
not start by bulk-generating cases or by interpreting the current 39-case
library as sequence-supervised data.

## Result

Completed offline on 2026-08-04.  The preregistered seed retained two
development families (`block_with_hole`, `counterbored_plate`) and one
family-isolated held-out family (`blind_hole_block`), with each source declared
as a self-authored deterministic oracle.  Deterministic OCP replay passed the
existing geometry gates for all three; two editability mutations per case also
passed.  Focused tests were 5 passed; full pytest was 80 passed and Ruff
passed.  The completion review supports only a separately scoped controlled
expansion proposal, not global case-library governance promotion, model-quality
claims, or runtime changes.
